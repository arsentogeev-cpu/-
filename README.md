# Telegram Stars Rewards Bot

Асинхронный Telegram-бот на Python 3.10+ и aiogram 3.x. Включает подписочный gate, SQLite, внутренний учёт Stars, рекламные задания через подключаемый API, рефералы, ежедневный бонус, промокоды, заявки на вывод и панель владельца.

> Баланс в этом проекте является внутренним учётом наград, а не балансом Telegram Stars. Сам бот не переводит Stars пользователям автоматически. Оператор выплачивает награду выбранным способом, затем нажимает «Одобрить»; только после этого бот отмечает сумму выплаченной и публикует отчёт. Не подтверждайте заявку до фактической выплаты.

## Требования

- Windows 10/11 и Python 3.10 или новее (инструкция ниже для PowerShell и VS Code).
- Telegram-бот, созданный через [@BotFather](https://t.me/BotFather).
- Информационный канал. Добавьте бота администратором, чтобы Telegram API мог проверять участников.
- (Опционально) канал выплат, где бот имеет право публиковать сообщения.
- (Опционально) рекламная платформа с API, соответствующим контракту ниже.

Владелец по умолчанию: `391992084`. Проверка ID выполняется для всех админских callback-действий и команд; кнопка панели создаётся только владельцу. Значение можно переопределить через `ADMIN_ID`.

## Установка и запуск в VS Code (Windows)

1. Откройте в VS Code папку проекта. Откройте терминал через **Terminal → New Terminal** и убедитесь, что текущая папка содержит `bot.py`.
2. Создайте виртуальное окружение и активируйте его в PowerShell:

```powershell
py -3 -m venv .venv
Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass
.\.venv\Scripts\Activate.ps1
```

Если команда `py -3` недоступна, используйте `python -m venv .venv`.

3. Выберите интерпретатор VS Code: `Ctrl+Shift+P` → **Python: Select Interpreter** → `.venv`.
4. Установите зависимости:

```powershell
python -m pip install --upgrade pip
python -m pip install -r requirements.txt
```

5. Создайте локальную конфигурацию из шаблона:

```powershell
Copy-Item .env.example .env
```

Откройте `.env` и задайте `BOT_TOKEN`, `REQUIRED_CHANNEL` (например, `@my_channel`) и `REQUIRED_CHANNEL_URL` (например, `https://t.me/my_channel`). Заполните `PAYOUT_CHANNEL`, если нужен публичный отчёт о выплатах. Бот должен быть администратором информационного канала и, для публикации отчётов, канала выплат. Никогда не публикуйте `.env` и не отправляйте токен бота третьим лицам.

6. Проверьте конфигурацию и синтаксис, затем запустите:

```powershell
python -m compileall -q .
python bot.py
```

Команда запуска: `python bot.py`. Остановить polling можно `Ctrl+C`. SQLite и загруженные фото хранятся в `data/`; каталог создаётся автоматически. FSM хранит временные состояния в памяти, поэтому при перезапуске незаконченный ввод нужно начать заново.

Для прямого использования встроенного терминала VS Code команды установки целиком:

```powershell
py -3 -m venv .venv
Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass
.\.venv\Scripts\Activate.ps1
python -m pip install --upgrade pip
python -m pip install -r requirements.txt
Copy-Item .env.example .env
python -m compileall -q .
python bot.py
```

После копирования `.env.example` отредактируйте `.env` до запуска.

## Размещение в Railway

Проект запускается как постоянно работающий polling-worker, HTTP-порт и публичный домен ему не нужны.

1. Запушьте проект в GitHub-репозиторий и в Railway создайте проект через **Deploy from GitHub repo**. Railway обнаружит `Dockerfile` и соберёт контейнер.
2. В настройках сервиса откройте **Variables** и добавьте переменные (значения берите из локального `.env`, но сам файл не загружайте):

```text
BOT_TOKEN
ADMIN_ID
REQUIRED_CHANNEL
REQUIRED_CHANNEL_URL
PAYOUT_CHANNEL
AD_API_TOKEN
FLYER_API_KEY
DATABASE_PATH=/app/data/bot.sqlite3
PHOTOS_DIR=/app/data/photos
```

`PAYOUT_CHANNEL`, `AD_API_TOKEN` и `FLYER_API_KEY` нужны только для соответствующих функций. Не добавляйте `.env` в GitHub; `.gitignore` и `.dockerignore` исключают его из Git и Docker-образа.

3. В Railway добавьте **Volume** к сервису и задайте mount path `/app/data`. Это обязательно: без volume SQLite-база и фото потеряются при пересборке или замене контейнера.
4. Нажмите **Deploy**. В логах должен появиться текст `Бот запущен`; сервис оставьте как постоянно работающий, не настраивайте для него web healthcheck.

Railway Free сейчас включает `$1` вычислительного кредита в месяц и лимит до `0.5 GB RAM`; это не безусловно бесплатная гарантия непрерывной работы. Расход зависит от фактического потребления, volume также тарифицируется. Следите за **Usage** в Railway; тарифы могут меняться.

## Настройка рекламной платформы

В разделе **Админ-панель → Настройки → Токен Botohub** задайте токен интеграции; либо укажите его в `AD_API_TOKEN` в `.env`. Endpoint фиксированный: `POST https://botohub.me/get-tasks-extended`, заголовок `Auth: TOKEN`, JSON `{ "chat_id": 123, "max_op": 6, "only_has_check": true }`.

Клиент использует `tasks[]` с полями `url`, `resource_id`, `completed`, а также общий `completed`, `skip` и `fake`. Ссылки отображаются как нейтральные кнопки «Задание N» без названия спонсора в тексте. Кнопка проверки повторно запрашивает статусы; награда начисляется только за `completed: true` у конкретного ресурса и не может быть получена повторно. Не задавайте `is_task` для этого endpoint: документация Botohub указывает, что режим заданий требует `/get-tasks` с `is_task: true`, тогда как этот бот использует только подписочные ресурсы расширенного API. Если токен не задан или API недоступен, раздел заданий сообщает о недоступности, сам бот продолжает работу.

### Flyer (дополнительный источник)

Добавьте отдельный API-ключ Flyer через **Админ-панель → Настройки → Ключ Flyer** или переменную `FLYER_API_KEY`. Ключ должен быть активным и иметь тип `tasks`; админ-панель проверяет его запросом `POST https://api.flyerhubs.com/get_me` перед сохранением.

Бот запрашивает до 6 заданий через `POST /get_tasks` с `key`, `user_id` и Telegram `language_code`, затем проверяет каждый статус через `POST /check_task` по `signature`. Ссылки показываются нейтральными кнопками в том же разделе «Заработок», что и Botohub. Награда начисляется один раз только при статусе `complete`. `waiting` означает, что Flyer ещё ожидает оплату (до 24 часов), поэтому Stars до `complete` не начисляются; `abort` и `unavailable` не награждаются.

Награда за задание и реферала по умолчанию составляет 0.5 Stars. Изменить их можно через `TASK_REWARD` и `REFERRAL_REWARD` в `.env`. На первом подтверждённом задании приглашённого реферер получает бонус один раз. Повторная награда за ту же пару пользователь/задание запрещена ограничением SQLite.

## Панель и сценарии

- Первый `/start` — проверка безопасности: нажмите кнопку с фруктом, указанным в сообщении; затем при необходимости подтвердите подписку на информационный канал. Старые зарегистрированные пользователи повторную CAPTCHA не проходят.
- `🎁 Бонусы` — `/daily` для ежедневного бонуса и `/promo CODE` для промокода.
- В панели владельца доступны заявки, статистика, рассылка, настройки каналов и API, фото/тексты и ZIP-резервная копия. Фото сохраняются в SQLite как Telegram `file_id` и локально в `data/photos/`.
- Добавление промокода владельцем: `/promo_add`, затем введите `CODE 1.5 100` (код, награда, лимит активаций).
- Вывод резервирует сумму на балансе. При отказе сумма возвращается; при одобрении учитывается как выплаченная. В канал выплат бот публикует пост после одобрения. Бот должен иметь право писать в канал.

Токен рекламного сервиса, введённый в админке, хранится в SQLite без шифрования; ограничьте доступ к файлу БД и резервным копиям. Удалите токен через смену значения в настройках, если доступ к серверу скомпрометирован.

## Доступность custom emoji

Заданные Telegram custom-emoji ID применяются в текстах сообщений через HTML `<tg-emoji>`. Bot API не предоставляет поля `custom_emoji_id` для обычных текстовых кнопок inline-клавиатуры, поэтому кнопки используют стандартные emoji-глифы. Это ограничение Telegram, а не настройка проекта.
